# CMaster

一个**能真正判题的** C 语言学习平台。12 章课程、48 个知识点、60 道在线练习，
每道题都会在你的机器上真实编译、真实执行、按测试用例逐条比对。

不用装编译器，不用配环境变量。解压、双击、打开浏览器。

```
双击 start.cmd  →  浏览器打开 http://127.0.0.1:5001
```

---

## 它解决了什么问题

学 C 最大的摩擦不在语法，在**第一步**：

> 装 MinGW、配 PATH、发现 gcc 不是内部或外部命令、换一个教程又是另一套装法……

大多数人卡死在这里，而不是卡在指针。

这个项目把「写代码 → 编译 → 运行 → 看结果」压缩成一次点击，
并且用 60 道题把「看懂」变成「写对」。判题不是模拟，是真的调 gcc。

## 功能

**学**
- **课程阅读**：章节侧边栏、上一节/下一节、打开即记已读、阅读进度条
- **站内搜索**：`/` 或 `Ctrl+K` 唤起，标题/正文加权排序，命中高亮，方向键选、回车跳
- **代码块**：自动识别语言并标注，一键复制

**练**
- **在线判题**：编译 → 逐用例执行 → 输出归一化比对，裁决 `AC/WA/TLE/RE/CE/SE`
- **逐用例反馈**：每个用例显示输入、期望输出、实际输出、耗时、stderr
- **游乐场**：自由写 C，自己喂 stdin，只看输出
- **代码自动保存**：草稿存在浏览器本地，刷新不丢

**看**
- **学习分析**：`/analytics`，做题量曲线、正确率、知识点掌握度雷达、薄弱分类表
- **知识图谱**：`/map`，12 章 48 节画成一张力导向关系图，可拖可缩、可聚焦未读、
  双击进入对应小节；关系分三类（章节结构 / 阅读顺序 / 先修依赖）
- **内存演示**：`/memory`，8 个场景 36 步，把栈帧/堆块/结构体填充逐字节画出来，
  指针用真实贝塞尔箭头连到它指的那几个字节；可自动播放、可单步、可键盘操作

**运维**
- **判题沙箱**：用户代码跑在内核配额下——Windows 用 Job Object（内存 / 进程数 / CPU /
  `KILL_ON_JOB_CLOSE`），Linux 用 `setrlimit` + 降权 + `PR_SET_NO_NEW_PRIVS` + `seccomp-bpf`。
  两个实现输出**完全相同的报告格式**，上层只认一份解析器。五项越界实验（死循环 / 内存炸弹 /
  命令逃逸 / 输出炸弹 + 对照组）可在 `/admin` 上真跑一遍自证，不是「检查版本号」式的自检
- **状态页**：`/ops`，判题耗时分布、失败率、请求数曲线、进程与磁盘；数据和 `/analytics`
  同源（同一个 `metrics.py` 打点），但看的是"服务还好不好"而不是"我学得怎么样"
- **故障归属**：`/ops` 顶上一张卡把失败分成两堆——**系统错误（SE，机器坏了，我该去修）**
  和**用户侧失败（WA/TLE/RE/CE，学生写错了，不怪我）**。AC 率的分母是「有对错的判题次数」，
  游乐场那种跑通次数不计入，否则「试了 20 次 Hello World」能把 AC 率稀释掉一半。
  裁决码定义集中在 `verdicts.py`，同一份表还挂在 `/api/verdicts`（公开，无需登录）
- **超时归因**：一个 TLE 徽章对学生没有信息量，所以再分三档——**算得慢**（CPU 吃满墙钟，
  去改复杂度）/ **在等**（CPU 几乎没用，查 `scanf`、死锁、sleep）/ **算等参半**。
  判据是 `cpu_ms / wall_ms` 的比值，`/ops` 上是一条三色比例条 + 四档图例
- **管理台**：`/admin`，沙箱后端与配额、六项状态计数、自检明细、判题指标、运行环境。
  和 `/ops` 的分工是「机器健康」对「判题过程」——指标取自同一个快照，两页 P95 永远一致。
  这一页能看到本机目录和内存，所以有 `CMASTER_ADMIN` 白名单；**没配的话页面顶部会挂一条
  黄横幅明说「任何登录账号都能打开」**——没配白名单是一个决定，不该悄悄发生
- **健康检查**：`/healthz`（存活，只看进程在不在）与 `/readyz`（就绪，查编译器 / data 可写 /
  沙箱是否降级 / 磁盘 / 沙箱初始化失败数）。两个探针**刻意分开**，混用会把
  「gcc 没装」这种重启治不好的问题变成重启风暴

**进度**
- **继续学习**：首页返回上次阅读的小节，推荐同章未通过练习和最近待复习错题。
- **账号与进度**：本地账号（PBKDF2-SHA256），进度、通过记录、错题本
- **自己的解法**：草稿按账号隔离；每题保留最近 10 次提交和最近通过代码，支持恢复与撤销恢复。
- **收藏与私人笔记**：知识点和练习题都能收藏、写笔记；`/notebook` 按章节、类型和关键词筛选。
  草稿立即保存在当前浏览器，点击保存后写入账号存档；多标签页编辑有版本冲突提示和撤销载入。
- **导出学习资料**：笔记本可下载 Markdown 笔记和 JSON 学习记录（含进度、提交代码、收藏与笔记），
  只导出当前登录账号，不包含密码或会话密钥。
- **故障不扣学习记录**：系统错误保留提交代码供重试，不增加尝试次数、不进入错题本。
- **错题本**：只收未通过的题，做对一次自动移出
- **连续学习天数**：今天还没学时从昨天起算，不会一早打开就看到归零
- **九枚成就**：由已读/已过/连击实时推导，不单独存状态
- **学习热力图**：近半年每日学习次数，分五档深浅

**键盘**
`/` 或 `Ctrl+K` 搜索 · `?` 快捷键面板 · `j` / `k` 上一节/下一节 · `Esc` 关闭

## 交互与动效

动效层独立在 `static/css/motion.css`，交互逻辑独立在 `static/js/ux.js`，
**全部是渐进增强**——把这两个文件删掉，站点照样能读、能写、能判题。

写动效只有三条规矩：

1. **只动 `transform` 和 `opacity`**，不动 `width` / `top`，否则滚动必然掉帧。
2. **动效可被打断**。用 `animation` 而不是长 `transition`，用户换页不用等它演完。
3. **尊重 `prefers-reduced-motion`**。系统里开了「减少动态效果」，全站动效降级为零。

站内搜索没有用倒排索引：120 条数据线性扫一遍就够，加索引是纯负担。
请求带 `AbortController` + 130ms 防抖，连打键盘不会排队。
所有高亮只对文本节点插 `<mark>`，不拼 HTML 字符串——搜索框是最容易被塞 XSS 的地方。

## 安装便携编译器

判题需要 `gcc`。项目**不写系统 PATH**，只在自己目录里找：

```
runtime/w64devkit/bin/gcc.exe
```

安装方式（一次性，约 64MB 下载 / 729MB 解压后）：

1. 下载 <https://github.com/skeeto/w64devkit/releases/download/v2.10.1/w64devkit-x64-2.10.1.7z.exe>
2. 放进 `runtime/` 目录，执行：

   ```
   cd runtime
   w64devkit-x64-2.10.1.7z.exe -y -o"./w64devkit"
   ```

   这是自解压程序，不需要额外装 7-Zip。解压后若多嵌套了一层
   （`w64devkit/w64devkit/bin`），把内层提到外层即可。

3. 验证：

   ```
   runtime\w64devkit\bin\gcc.exe --version
   ```

`judge.py` 的查找顺序是：`runtime/w64devkit/bin` → `runtime/mingw64/bin`
→ 系统 PATH 里的 `gcc`/`cc` → `C:\msys64`、`C:\mingw64`、`C:\MinGW`、CodeBlocks。
所以就算你机器上已经装了别的编译器，也能直接用。

## 重新生成内容

改完 `tools/content_*.py` 之后：

```
runtime\venv\Scripts\python.exe tools\build_content.py
```

这会做两件事：

1. 把 Python 数据装配成 `data/courses.json` 与 `data/question_bank.json`；
2. **门禁**：用每道题的参考答案跑它自己的测试用例，全部 `AC` 才放行。

门禁不是可选项。手写测试用例的期望输出，人一定会算错几道；
上线后的表现是最恶劣的那种——**学生写对了，系统判他错**。
所以任何一题不是 AC，构建就失败，不写文件。

```
python tools/build_content.py --no-gate     # 只装配，调试用
python tools/build_content.py --gate-only   # 只跑门禁
```

改完内存演示场景（`tools/build_demos.py`）之后单独跑：

```
runtime\venv\Scripts\python.exe tools\build_demos.py
```

它会把 8 个场景的每一步都重新算一遍地址与填充，写进 `data/memory_demos.json`。
装配完一定要用浏览器开 `/memory` 扫一眼——地址错位是**不会报错**的，只会画歪。

## 验证

学习流程回归（临时目录，不使用真实账号；不需要编译器）：

```bash
python -m unittest discover -s tests -v
python tools/build_training.py --check
```

涵盖训练数据缺失与只读目录、旧账号迁移、同名文件隔离、并发读课、系统故障、
提交历史、首页推荐，以及全部课程和做题页面。判题结果在这些测试中采用可控返回值；
真实编译执行仍使用下方的 `tools/gate.py` 验证。

浏览器回归先启动 `python tests/browser_fixture.py`，再运行
`node tests/learning-flow.cjs` 与 `node tests/notebook.cjs`（需本地 Playwright，默认使用 Edge，可设置
`CMASTER_BROWSER=chromium`）。该服务仅供测试，使用临时账号和模拟裁决。

改完任何一处都跑这几道闸门。下面每行都**能被机器判对错**，不靠眼睛看：
**六条命令覆盖前八行**（`crawl.py` 一次跑完全站 / 静态资源 / 接口契约三项），
最后两行是 puppeteer 脚本，要浏览器，不在那六条里。

```
rem 先登录取一份 cookie，crawl.py 靠它验登录态；没有这份 jar 它会直接退出码 3
curl -s -c "%TEMP%\cmck.txt" -d "username=verify01&password=cmaster2026" http://127.0.0.1:5001/login

runtime\venv\Scripts\python.exe tools\gate.py       # 题库：60 题 157 用例全 AC
runtime\venv\Scripts\python.exe tools\crawl.py      # 全站：134 页 + 29 个静态资源 + 4 个接口契约
runtime\venv\Scripts\python.exe tools\probe_tle.py  # 超时归因：五档断言，不符退出 1
runtime\venv\Scripts\python.exe tools\check_runners.py  # 两个 runner 的契约面对拍：7 项
for f in static/js/*.js static/js/lib/*.js; do node --check "$f"; done   # 逐个语法检查

rem 判题器：告警全开编一遍。它跑在沙箱里，出事没人看得见，先让编译器看
runtime\w64devkit\bin\gcc.exe -Wall -Wextra -O2 -std=gnu11 -c sandbox/runner_win.c -o nul
```

`check_runners.py` 不验「能编译」（本机没有 Linux 工具链），它验的是**两份实现
是否还守同一份契约**：时限宽限、CPU 配额公式、16 个报告键、`CPU 时间超限` 这条
note、以及「墙钟在收尸之前定格」这一条顺序不变量。最后一条不违反任何语法，编译器
一个字都不会说，但 300ms 时限下它能直接把「算得慢」判成「在等」。确实不能对称的
差异（Linux 的 `t0` 在 `fork` 之前）写进脚本的「已知差异」并给出理由——想「顺手
补齐对称」的人会先看到为什么不对称。

`verify01` 是本地验收账号（口令就写在上面，故意让人能直接跑通闸门）。
**它只该活在本地 `data/users.json` 里**——公网部署前要么删掉，要么改口令，
别把文档里的口令当成产品的一部分。

`crawl.py` 值得单独说四句：

- **它的模板残留检测不能只搜 `{{`**——C 的二维数组初始化 `int a[2][2] = {{1,2},{3,4}};`
  长得一模一样，会稳定误报三条。现在的判据是「花括号内含字母且不含 HTML 标签」才算残留。
- **未登录时它会直接判失败（退出码 3），而不是报一片绿**。Flask 未登录 302 到 `/login`，
  `urllib` 跟着跳拿到 200，所有页面全是同一份登录页——这种假绿曾经掩盖过一次
  `/ops` 的 500。所以它有一份 `PROTECTED` 名单，命中登录页就单独记 `denied`。
  接口也一并 GET：页面全 200 不代表 `/api/verdicts` 没坏。
- **403 单独记「预期拒绝」，不算异常**。配了 `CMASTER_ADMIN` 之后 `/admin` 会拒绝
  不在名单里的账号，那是加固生效，不是站点坏了；混进「异常状态码」会让人把加固
  读成事故。想验这条分支得换实例：给新进程设 `CMASTER_PORT=5002` 和
  `CMASTER_ADMIN=someoneelse`，再 `CMASTER_BASE=http://127.0.0.1:5002` 跑一次 `crawl.py`。
- **读 cookie jar 时 `#HttpOnly_` 是数据不是注释**。curl 给 HttpOnly 的 cookie 行加这个
  前缀，而 Flask 的 session 恰好就是 HttpOnly——按 `startswith("#")` 跳过的写法会把唯一
  有用的那一行扔掉。它平时不露脸（jar 里只要还有别的非 HttpOnly cookie 就照样能登），
  重登一次、jar 里只剩 session 一条，就突然报「7 个受保护页面被抓成了登录页」，
  让人误以为是登录过期。

## 判题是怎么做的

```
学生代码
  ↓ 写进临时目录 main.c
  ↓ gcc -std=c11 -O2 -Wall -Wextra -fno-asm -o main.exe main.c -lm
  ↓ sandbox.run()：交给平台宿主（Job Object / rlimit+seccomp）去执行
  ↓ 每个用例：stdin 喂输入，墙钟 3 秒强杀，输出/错误分别截断
  ↓ 输出归一化（CRLF→LF、去行尾空白、去首尾空行）
  ↓ 逐字符比对
  ↓ 裁决 + 逐用例详情（含 cpu_ms / peak_mem）
```

几个容易踩的点：

- **gcc 要能找到自己的 `cc1` / `as` / `ld`**。不把编译器所在目录塞进
  子进程的 `PATH`，会报 `cannot execute cc1`。`judge._clean_env()` 就是干这个的。
- **输出必须归一化**。`printf("7\n")` 和期望的 `"7"` 在字符串层面不相等，
  但学生是对的。不归一化会大面积误判。
- **首个非 AC 决定最终裁决，但仍然跑完全部用例**，这样学生一次就能看全所有问题。
- **超时只能看沙箱报告的 `timed_out` 字段，不能看退出码**。宿主自己用 124 表示超时，
  而用户程序 `return 124` 是合法的——早年按退出码判断，把一道参考答案正好
  `return 124` 的题误判成 TLE。
- **时限是契约，宽限不能宽到改变结论**。两个宿主统一 `LIMIT_GRACE_MS = 150`，
  实测 TLE 的 `wall_ms` 稳定落在 3150ms 附近。曾经的宽限是 500ms，导致「跑了 3.3 秒
  的程序判通过」，而报告上写着「3 秒内没结束」。
- **`wall_ms` 在「进程结束/被判超时」那一刻定格，不含收尸时间**。早先记在 `wait4` /
  join 读线程之后，多记 180ms：3 秒的题报告写 3.6 秒，而超时归因正是拿 `wall_ms`
  当分母的——分母错一点，300ms 的时限里「算得慢」会被算成「在等」。

## 安全边界

判题执行的是**陌生人写的 C 代码**。这件事现在有四层防线，每层挡的东西不一样：

| 层 | 机制 | 挡什么 |
|---|---|---|
| 资源量 | Windows Job Object / POSIX `setrlimit` | 死循环、内存炸弹、fork 炸弹、输出炸弹 |
| 进程拓扑 | `KILL_ON_JOB_CLOSE` / `PDEATHSIG` + `setpgid` | 判题进程崩了留下孤儿 |
| 权限 | 普通用户 / `nobody` + 容器 `USER 10001` | 改系统文件、读别人的东西 |
| 行为 | Linux `seccomp-bpf` 黑名单 | `execve` / `socket` / `ptrace` / `mount` / `setuid` |

要讲清楚的两件事：

1. **Windows 侧只有前三层**。Job Object 能限资源，管不了行为——挡不住读
   `C:\Users\…`、挡不住连外网。那边靠的是权限，不是 syscall 过滤。
   能力边界说清楚，比一个「全栈安全」的形容词可信。
2. **沙箱坏了就拒绝判题，不裸跑**（fail-closed）。区分两种「没沙箱」：
   本来就拿不到（没编译器编不出宿主）→ 降级并计数；本该可用却初始化失败 →
   判 `SE` 并拒绝执行。沙箱坏了之后裸跑用户代码，比一开始没有沙箱更糟，
   因为它把降级藏起来了。

公网部署仍建议再加：TLS 终止、按 IP 限流、把 `/admin` 单独拆到内网或另一个端口
（`CMASTER_ADMIN` 只是一个 env 白名单，不是权限系统：没有角色、没有审计）。
`docker-compose.yml` 已经把「只绑 `127.0.0.1`、只读根文件系统、`cap_drop: ALL`、
`no-new-privileges`、`mem_limit` 与 `pids_limit`」写成了默认值。

**已知未证明的一块**：`runner_linux.c` 编写时开发机没有 Linux 环境，所以它
**只有编译证据，没有运行证据**，五组越界实验一次都没在真内核上跑过。

编译证据是补出来的：用 `zig cc` 交叉编译到 `x86_64-linux-gnu`，
`-O2 -std=gnu11 -Wall -Wextra` 下**零告警**，ELF 头核对为 64 位 x86-64、
要求 glibc ≤ 2.17（bookworm 是 2.36），二进制里能查到 `seccomp`/`prctl`/`setrlimit`。
（这份产物是 zig 自带 glibc 链出来的，**不能拿去部署**，镜像里由 bookworm 自己的
gcc 现编。它的唯一用途是证明源码可编译。）

补偿方式是让代码自己证伪——镜像构建期就编译它（编不过就炸 build），首次部署后
在 `/admin` 点「重跑自检」，四项越界全绿才算它成立。Windows 侧的五项自检与
五种裁决均已实测通过。

## 部署（Docker）

```bash
# 构建 + 启动（只监听 127.0.0.1:5001）
echo "CMASTER_SECRET=$(openssl rand -hex 32)" > .env
docker compose up -d --build

# 看启动日志里的沙箱结论（这一行是重点，不是装饰）
docker compose logs cmaster | head -20

# 存活 / 就绪
curl -f http://127.0.0.1:5001/healthz
curl -f http://127.0.0.1:5001/readyz | python -m json.tool
```

三个设计决定，都写进了对应文件的注释里：

- **`/healthz` 与 `/readyz` 不能混用。** 前者只回答「进程还在吗」，给编排系统决定
  要不要重启；后者回答「现在能不能判题」，不适合时 503 但**不重启**。
  把「gcc 没装」这种重启治不好的问题塞进存活探针，会让容器被反复重建，
  从一个故障变成一串故障。
- **根文件系统只读，但 `/tmp` 不能加 `noexec`。** 判题把用户代码编译到 `/tmp` 再
  exec 它，`noexec` 会让所有题变成 RE。加固不是越严越好，是限在「不影响功能」那条线上。
- **沙箱宿主在构建期编译。** 只读根文件系统下运行期写不进去；更重要的是
  「编不过」应该炸在 `docker build`，而不是变成运行期的一次静默降级。

## 技术选型说明

**为什么是 Flask + JSON 文件，不是数据库？**
内容层是只读的、构建期就确定的；用户层每人一个 JSON，读写量小。
引入数据库只会增加部署门槛。真要多人用，把 `data/progress/` 换成 SQLite 即可，
接口不用动。

**为什么自写 Markdown 转换器？**
需要离线可用、不引 CDN。教学文档只用到标题/列表/引用/代码块/粗体/链接
这几种语法，多引一个依赖不值得。C 语法高亮也是自己写的 token 状态机
（`tools/md2html.py`），因为要处理「未标注语言的代码块其实是示意图」这种情况。

**为什么 CodeMirror 5 而不是 6？**
5 的 `clike` 模式内置 C 支持，体积小（lib + 模式 + 主题共 224KB），
API 简单到可以直接 `fromTextArea`。6 需要打包器，和「无构建步骤」冲突。

**为什么内存演示的地址是构建期算好的，不是前端算的？**
地址得自洽：`&a[1]` 必须等于 `&a[0] + 4`，`&s.b` 必须落在 `s` 里面加上偏移，
递归每深一层栈指针要减掉整个帧大小。这类约束分散在两侧各算一遍，
迟早会出现「箭头指向格子外一个像素」这种只在某个场景才出现的错。
所以 `build_demos.py` 一次性把地址、填充字节、每个变量的宽度都算完写进 JSON，
前端**连一次地址都不复算**，只负责把给到的数字摆上去。
代价是改场景要重跑构建——这个代价换来的是几何可以被脚本审计（见「验证」最后一行）。

## 已知限制

- 判题是**逐用例串行**的，一题 4 个用例就是 4 次进程启动，约 200ms。
  想更快可以在一次进程里跑多组输入（需要改造题目的 I/O 约定）。
- 没有代码相似度检测，学生可以直接粘贴参考答案。
- 参考答案存在 `data/answers.json`，任何能读服务器文件系统的人都能看到。
  这在「本机教学」场景下可以接受，公网部署必须换掉。
- 移动端只做了基本适配，编辑器在小屏上体验一般。

## 升级已有数据

- 升级前保留整个 `data/` 目录。新版账号仍使用原有用户名和密码；进度文件使用完整用户名的
  SHA-256 标识，避免特殊字符、截断和 Windows 文件名大小写造成进度串号。
- 首次读取时，仅有一个账号对应的旧进度会自动复制到新存档，旧文件保留。
  若旧文件曾由多个账号共用，新版会显示提示并启用独立存档，保留原件供确认归属后恢复。
- 旧错题本中的系统错误会自动移除，并保留当时的代码。旧版本没有完整的裁决历史，
  无法准确还原的历史尝试次数保持原值；新版系统错误不再增加次数。
- `data/training.json` 是课程卡片，不含个人成绩，随仓库和镜像发布。
  缺失时启动会尝试生成；只读目录中也能使用生成的内存副本。
- 最新草稿存在当前浏览器，提交过的代码保存在服务器。新浏览器登录后可恢复最近提交，
  每题独立保留最近通过代码与最近 10 次提交。多账号环境不会自动认领旧版共用浏览器草稿，
  旧草稿原值仍保留在浏览器中。
- 可用 `CMASTER_DATA` 指定账号和进度目录；空目录会回退读取随项目发布的课程内容。
